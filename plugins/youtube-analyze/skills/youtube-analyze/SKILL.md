# Разбор канала

Скилл превращает данные канала в решения: что снимать дальше и о чём писать в Telegram. Это не дашборд с цифрами. Человеку нужны выводы и идеи, поэтому цифры только как доказательство.

## Шаг 0. Первый запуск (приветствие один раз)

Проверь, есть ли файл-метка `~/.claude/youtube-analyze.seen` (в домашней папке пользователя).

- Файла нет: покажи блок «Что я умею» ниже, затем создай файл с одной строкой с сегодняшней датой. Только после этого иди дальше.
- Файл есть: приветствие не показывай. Сразу к шагу 1.
- Файл не удалось прочитать или записать: молча пропусти приветствие, не сообщай об этом пользователю.

Блок «Что я умею» (показывать как есть, коротко):

> Я разбираю YouTube-канал и подсказываю, что снимать и что писать дальше. Как меня вызывать:
> - `/youtube-analyze` — полный разбор канала: что залетело, что просело, идеи для видео и для Telegram.
> - `/youtube-analyze идеи для видео` — только идеи роликов на основе лучших видео и комментариев.
> - `/youtube-analyze идеи для постов` — только идеи постов для Telegram-канала.
> - `/youtube-analyze комментарии` — что просят и о чём спрашивают зрители.
> - `/youtube-analyze настройка` — проверить, что подключение к YouTube работает, и показать, чего не хватает.
> - `/youtube-analyze шортсы` — 3 фрагмента из лучшего видео для Shorts.
> - `/youtube-analyze сравни с @канал` — сравнение с другим каналом.
> - `/youtube-analyze почему не пошло <ссылка на видео>` — разбор одного ролика.
> Можно и обычными словами: «проанализируй мой канал».
>
> **Для работы мне нужен ключ YouTube Data API v3.** Он бесплатный, получить его можно минут за 10 (нужен VPN, если Google у тебя недоступен). Как достать:
> 1. Зайди на console.cloud.google.com и создай проект (название любое).
> 2. «APIs & Services» → «Library» → найди **YouTube Data API v3** → «Enable».
> 3. «APIs & Services» → «Credentials» → «Create credentials» → «API key».
> 4. Открой созданный ключ («Edit API key») и в «API restrictions» оставь только YouTube Data API v3.
> 5. Скопируй ключ. Он длинный и начинается с `AIza`.
>
> Это сообщение показано один раз.

**После приветствия: запроси ключ.** Если инструментов YouTube MCP нет или пробный вызов из шага 1 не проходит из-за ключа, спроси пользователя: «Ключ уже есть? Если нет, пройди пять шагов выше. Когда он будет, выбери: вставь его сюда, и я подключу сам, или подключи сам командой, которую я дам». Дальше:

- **Пользователь вставил ключ в чат.** Предупреди одной строкой, что ключ останется в записи этого чата, и посоветуй ограничить его в Google Cloud до YouTube Data API v3 (шаг 4). Затем подключи сервер сам командой ниже, подставив ключ, и скажи, что нужен перезапуск Claude Code. Ключ в своих ответах и в выводе команд не повторяй и маскируй (`AIza***`).
- **Пользователь хочет подключить сам.** Дай команду с заглушкой `ВСТАВЬ_КЛЮЧ`, не спрашивай сам ключ.

Команда для Windows (имя сервера идёт сразу после `add`, перед флагами):

```bash
claude mcp add youtube --transport stdio --scope user -e YOUTUBE_API_KEY=ВСТАВЬ_КЛЮЧ -- cmd /c npx -y @kirbah/mcp-youtube
```

На macOS и Linux то же самое, но вместо `cmd /c npx` пиши `npx`. После перезапуска проверь подключение командой `claude mcp get youtube`: нужен статус «Connected».

## Шаг 1. Проверка подключения (до любого сбора данных)

Убедись, что инструменты YouTube MCP доступны: `getChannelStatistics`, `getChannelTopVideos`, `getVideoDetails`, `getVideoComments`, `getTranscripts`, `searchVideos`.

Если их нет, не придумывай данные. Скажи, что подключение не настроено, и дай три шага:
1. Получить бесплатный ключ YouTube Data API v3 в Google Cloud Console.
2. Добавить MCP-сервер `@kirbah/mcp-youtube` в настройки Claude Code с переменной `YOUTUBE_API_KEY`.
3. Перезапустить Claude Code и снова вызвать скилл.

Ключ запрашивай по порядку из шага 0 (после приветствия) и не выводи его на экран. Он живёт только в настройках у пользователя.

**Пробный вызов.** Инструменты на месте, но это ещё не значит, что всё работает. Сделай один дешёвый вызов `getChannelStatistics` для канала пользователя (1 единица квоты). Только если он прошёл, иди к шагу 2. Если не прошёл, объясни причину по таблице и остановись:

| Что видишь | Что сказать пользователю |
|---|---|
| Ошибка сети, таймаут, «не удалось подключиться» | YouTube и сервисы Google недоступны из твоей сети. Включи VPN на весь компьютер (не только в браузере) и запусти заново. |
| 400 или «API key not valid» | Ключ неверный или не вставлен. Проверь переменную `YOUTUBE_API_KEY` в настройках MCP-сервера. |
| 403 «has not been used» или «disabled» | В Google Cloud проекте не включён YouTube Data API v3. Включи его на странице API проекта. |
| 403 «quotaExceeded» | Дневная квота ключа (10 000 единиц) кончилась. Квота обновляется раз в сутки, повтори завтра. |
| Канал не найден | Проверь handle или ссылку. Handle пишется с @. |

**Режим без подключения.** Если подключение настроить не получается, не бросай человека. Предложи прислать данные руками: список последних видео с просмотрами и датами (из YouTube Studio, раздел «Контент») и 20–50 комментариев под лучшим и худшим видео. Дальше шаги 4 и 5 работают так же, но заранее скажи, что идеи из комментариев будут точны только в пределах того, что он прислал.

**Команда `настройка`.** На `/youtube-analyze настройка` не разбирай канал, а пройди по установке по шагам: что есть, чего не хватает, пробный вызов, итог «готово» или «не хватает вот этого».

`findConsistentOutlierChannels` не используй: ему нужна отдельная база, у большинства её нет.

## Шаг 2. Какой канал и что нужно

Возьми канал из сообщения (ссылка, @handle или ID). Если не указан, спроси один раз. Если дан только @handle или название, найди ID через `searchVideos` с `type=channel` и запомни его до конца разговора.

Если из запроса не ясно, что нужно, задай один вопрос: полный разбор, идеи для видео, идеи для постов или разбор одного ролика. Всё остальное решай сам.

## Шаг 3. Сбор данных

Следи за квотой: у ключа 10 000 единиц в день. Дорогие вызовы `searchVideos` (100) и `getChannelTopVideos` (101) делай по одному разу. Остальные дешёвые или бесплатные, ими не жалей.

1. `getChannelStatistics`: подписчики, всего просмотров, число видео, возраст канала.
2. `getChannelTopVideos` на 15–20 видео.
3. `searchVideos` с `channelId`, `type=video` и `order=date` на последние 15–20 загрузок. Параметр `query` обязателен и не может быть пустым: возьми название канала. Так видно не только хиты, но и обычные ролики, включая Shorts.
4. `getVideoDetails` на все собранные видео: просмотры, лайки, комментарии, длительность, дата, заголовок.
5. `getVideoComments` на 3 лучших и 3 худших видео, до 50 комментариев на видео, без ответов (`maxReplies` не задавай).
6. `getTranscripts` в режиме `key_segments` на 3 лучших и 3 худших: нужны первые секунды (хук). Если пришёл пустой результат (`null`), так бывает, когда сервер не достаёт до YouTube из сети пользователя, пиши [нет данных] про хуки и не выдумывай их.
7. Если есть возможность открывать картинки: превью по адресу `https://img.youtube.com/vi/<ID видео>/hqdefault.jpg` для тех же шести видео. Если открыть нельзя, прямо скажи и не описывай превью, которых не видел.

Для разбора одного ролика: `getVideoDetails` на него, транскрипт начала, комментарии, и сравни с медианой канала.

## Шаг 4. Анализ

1. **Что залетело.** Shorts (до 60 секунд) и длинные ролики считай отдельно: у каждого формата своя медиана и свои хиты. Список `getChannelTopVideos` смешивает форматы, раздели его по длительности. Посчитай медиану просмотров по каналу. Залетевшими считай ролики от 2 медиан и выше. Сделай поправку на возраст: свежее видео не сравнивай с годовым.
2. **Что у них общего.** Тема, формат, длина, формула заголовка, первые 10–15 секунд (из транскрипта), день публикации, оформление превью, если смотрел. Выводи закономерность только при минимум трёх совпадениях.
3. **Что просело.** Те же признаки, но у просевших. Ищи отличие от залетевших, а не просто «плохо».
4. **Что говорят зрители.** Сгруппируй комментарии: вопросы, просьбы «сделай про…», возражения и споры, боли («не получается», «слишком сложно»), что хвалят. Считай, сколько людей про одно и то же. Повторяющийся запрос важнее одного яркого комментария.

Размер канала определи по числу подписчиков: до 1 тыс., 1–10 тыс., 10–100 тыс., больше 100 тыс. От него зависят советы. Маленькому каналу не говори про монетизацию и спонсоров, ему нужны темы и упаковка. Сравнивай канал прежде всего с ним самим (медиана, лучшие и худшие ролики), а не с чужими «нормами».

## Шаг 5. Что выдать

Короткий разбор аналитика, не форма. Порядок:

1. **Коротко.** Ровно 3 предложения: где канал сейчас и что у него сильнее всего; что тормозит больше всего; какое одно изменение даст больше всего прямо сейчас.
2. **Что залетело и почему.** 3–5 роликов. Для каждого одна строка: название, просмотры против медианы, главная причина.
3. **Что просело.** 1–2 ролика и правки, расставленные по силе эффекта, а не по лёгкости. Каждая правка с конкретным действием, не «улучшить превью».
4. **Что просят зрители.** 3–5 повторяющихся тем из комментариев, с оценкой «часто» или «разово».
5. **5 идей для следующих видео.** Идеи разные по теме и подаче, без повторов. Для каждой:
   - рабочий заголовок;
   - откуда идея: какое видео или какие комментарии её подсказали (без источника идею не пиши);
   - как её найдут: через поиск, через рекомендации или это сезонная тема с датой. В пяти идеях должно быть минимум два разных способа;
   - первая фраза ролика, которая ловит интерес;
   - превью одной фразой в 10–15 слов: кто или что в кадре, какой текст, какие цвета;
   - длина в минутах по нормам канала;
   - срочность: «снять сейчас» только для реально горячей темы, иначе «в любое время».
6. **План на 4 недели.** По одному видео в неделю из этих идей, с короткой причиной порядка. Чередуй идеи для поиска и для рекомендаций, не ставь подряд два тяжёлых по производству.
7. **5 идей для постов в Telegram.** Для каждой: из какого видео или комментариев и формат. Форматы: анонс видео, «кухня» (как делал, что не получилось), итог и вывод, ответ на частый вопрос из комментариев. Один пост в неделю делай без видео, из комментариев. Пост пиши под формат Telegram, а не пересказом транскрипта, и в конце давай ссылку на видео.
8. **3 фрагмента для Shorts.** Только если просили, или если есть транскрипт лучшего видео. Три места, которые понятны без остального ролика: где они в видео (таймкод, если он есть в транскрипте, иначе пометка [нет таймкода] и цитата начала фразы), новая первая фраза для вертикального формата и чем клип заканчивается, чтобы смотрели по кругу.
9. **Шаг на эту неделю.** Одно действие, которое можно сделать за день, с проверяемым результатом.

Если просили только идеи для видео, постов или комментарии, выдай соответствующие пункты и кратко опорные данные.

Всё оценочное помечай `[оценка]`, а то, чего нет в данных, помечай `[нет данных]`. Не заполняй такие места правдоподобными цифрами.

В конце спроси, сохранить ли отчёт файлом. Если да, сохрани как `youtube-analyze-ГГГГ-ММ-ДД.md` в текущей папке.

## Правила

- Не утверждай ничего про CTR, показы, удержание и источники трафика. Их нет в открытых данных, они только в YouTube Studio. Если вывод зависит от них, так и скажи и предложи посмотреть цифру в Studio самому.
- Мало данных: меньше 10 видео или меньше 20 комментариев на видео. Скажи, что выводы предварительные, и не рисуй закономерности из двух точек.
- Не пиши, что причина найдена. Пиши «вероятная причина», если нет явной связи. Совпадение признаков не доказывает причину.
- Комментарии не цитируй дословно и не называй авторов. Описывай, что просят, своими словами и с количеством.
- Чужие каналы: описывай переносимую закономерность, а не предлагай копировать заголовок, превью или ролик.
- Не выдумывай цифры. Каждая цифра в ответе взята из данных, которые ты получил. Если не получил, не называй.
- Работай только на чтение. Ничего не публикуй, не комментируй и не меняй на канале.
- Тон спокойный и честный, без разноса. Если канал просел, начни с того, что можно исправить.
